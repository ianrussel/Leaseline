Customers

Each row's local-part routes inbound email - a tenant emailing <local-part>@your Resend receiving domain becomes a pending message in that customer's owner's inbox (see api/inbound-email.js). Leave local-part blank to default to the owner email's own name (e.g. owner@example.com → owner) - the owner's account email itself stays reserved for sign-in and business correspondence with us, never used as the literal tenant-facing address. Give it an explicit value (e.g. sunsetapartments) when a customer wants something more memorable. Owner must already be a Supabase user (Authentication → Users → Add user) - there's no signup flow yet. Each local-part is exclusive to one customer - the database rejects a duplicate outright, it's never silently shared or reassigned.

If a customer wants tenants to keep emailing their existing business address instead of learning a new one: that's only possible via a forwarding rule set up on their end (e.g. Gmail → Settings → Forwarding and POP/IMAP → forward to their local-part address here), not something this app can do for them - Resend can only receive mail for domains it's configured to receive for, never an arbitrary customer's real inbox provider.
